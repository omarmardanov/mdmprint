# Авторизация по SMS

Вход в личный кабинет по номеру телефона + код из SMS. Живёт в прототипе `prototypes/usluga.html`.
**Тот же компонент-модалка `.cbm`, что «Заказать звонок» / «Заявка» / ЧАВО** — не отдельная форма, а
4-я форма того же движка. Десктоп = центр-модалка, мобилка = нижняя шторка (адаптив компонента).

**Тестовый код в прототипе: `1234`.**

---

## Флоу (2 шага + успех)

1. **Шаг 1 — телефон + согласие.** Поле телефона (маска `+7 (___) ___-__-__`) + чекбокс согласия
   на обработку ПДн и получение кода (юридический минимум) → кнопка «Получить код».
2. **Шаг 2 — код из SMS.** Заголовок «Введите код из SMS» + номер строкой ниже (серым, тем же капсом);
   4 ячейки кода (автопереход, вставка, backspace); строка «Отправить код повторно через 1:00»
   (по истечении минуты → ссылка «Отправить код повторно»); ссылка «Изменить номер» (назад к шагу 1).
3. **Успех.** Экран «Вход выполнен» (иконка-галка как в заявке, квитанция «Телефон», кнопка «Хорошо») →
   модалка закрывается, в шапке появляется личный кабинет.

## Состояния (все заложены)

**Шаг 1:** пустой · заполнен · ошибка номера (неполный) · нет согласия · отправка (loading) ·
SMS не ушла (ошибка сервера).
**Шаг 2:** код отправлен (таймер) · ввод · неверный код · код истёк · много попыток (блокировка) ·
проверка (loading) · повтор доступен · успех.

> Референс всех состояний собран в песочнице `archive/sandboxes/_sandbox-auth.html` (галерея карточек).

## Шапка после входа (личный кабинет)

Кнопка «Войти» → после входа то же место показывает ЛК:
- **имя в профиле заполнено** → **инициалы** фирменным шрифтом AttractiveCond («Иван Иванов» → «ИИ»,
  «Иван» → «И») + подпись = имя; в выпадашке — имя + номер;
- **имя не заполнено** → дефолт-иконка + подпись «Кабинет»;
- **мобилка** → всегда дефолт-иконка (без инициалов/имени), независимо от входа.

Выпадашка: имя + номер → «Личный кабинет» · «Мои заказы» · «Выйти».
Демо-хук: `const PROFILE_NAME` в скрипте авторизации (пусто = «Кабинет»; имя → инициалы). В бою имя
приходит с бэка.

## Реализация (для разработчика)

- **Компонент:** переиспользован `.cbm-*` из usluga (бэкдроп, карточка, поля, чекбокс, невалид, ошибка,
  `.cbm-done` для успеха). Своё — только: 4 ячейки кода (`.auth-code`/`.auth-cell`), таймер
  (`.auth-resend`), инициалы+меню ЛК (`.u-av`/`.umenu`), спиннер (`.mk-btn.is-loading`).
- **Обязательные детали при работе с `.cbm`** (иначе форма кривая):
  - кнопки действия — класс **`.cbm-submit`** (ширина 100%);
  - контент каждого экрана — в элементе с атрибутом **`[data-role]`** (мобильная шторка вешает на него
    боковые поля, скролл, липкий заголовок; без него — контент упирается в края);
  - крестик — svg с `width/height="14"`.
- **Триггер в шапке:** одна кнопка `#authBtn` — переключатель (не залогинен → открыть модалку;
  залогинен → выпадашка). `m-keep` не прячем (иначе мобильный `!important` ломает показ).
- **A11y:** фокус-трап в модалке, `role="alert"`/`aria-live` на ошибки и таймер, `aria-expanded` на
  меню ЛК, `autocomplete="one-time-code"` на первой ячейке (автоподстановка кода из SMS), автофокус.

## Что нужно от бэкенда (интеграция)

Прототип имитирует; для боя нужно подключить:
1. **Отправка SMS** по номеру (шаг 1 → шаг 2). Ошибки: не отправлено / лимит запросов.
2. **Проверка кода** (шаг 2). Ответы: верно / неверно / истёк / **лимит попыток** (поведение после
   N неверных — блокировка на время? новый код?).
3. **Профиль** — имя (для инициалов/приветствия), связь с историей заказов, корзиной.
4. Согласие на ПДн — фиксировать факт и версию политики (152-ФЗ).

## Открытые вопросы (сверить с продом mdmprint.ru)

- **Длина кода** — в прототипе 4 цифры. На проде — 4 или 6?
- **Тексты ошибок** — формулировки под прод.
- **Лимит попыток** — сколько неверных до блокировки и что дальше.
- **Мобильные выпадашки ЛК** — сейчас «десктопные», отдельно допилить под мобилку (не критично).
- `PROFILE_NAME` в прототипе — демо-константа; вернуть в `''` и брать имя из профиля.
