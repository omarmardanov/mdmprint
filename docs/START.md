# С чего начать

Эта страница — вход в документацию. Прочитать целиком, займёт минут пять.
Дальше идти только в тот файл, который нужен под вашу задачу. Читать всё подряд не надо.

## Что за работа

У mdmprint.ru уже есть страницы каталога. Мы не делаем сайт с нуля — меняем этим страницам
дизайн. Значит это перенос контента в новый шаблон: старые адреса сохраняем, редиректы не плодим.

Дизайн сдан не картинкой, а свёрстанной страницей: `prototypes/usluga.html`. Там десктоп, мобилка
и работающие интерактивы. Это важно для планирования: задача — перенести готовый код в тему,
а не верстать заново по макету. В странице уже решены вещи, которые по картинке не видно —
размеры тач-целей, залипающий hover на телефоне, зум полей в iOS, обрезка каруселей по краю
экрана. Всё это ловилось на реальных устройствах. Вёрстка заново вернёт эти баги.

Одна страница `usluga.html` содержит сразу шапку, футер, формы и шаблон карточки услуги.
Шапка, футер и формы — сквозные, они лягут на весь сайт.

## Что вам передали

```
prototypes/usluga.html          эталон: шапка, футер, формы, страница услуги
prototypes/tehnologii-top.html  верхний блок раздела «Технологии печати»
prototypes/materialy-top.html   то же для материалов
prototypes/kit.html             витрина компонентов
assets/css/tokens.css           переменные: цвета, отступы, шрифтовые размеры
assets/css/kit.css              компоненты: кнопки, карточки, ленты, формы
assets/css/fonts.css            подключение шрифтов
assets/fonts/                   AttractiveCond и Roboto, self-host
```

Живая версия открывается по ссылке, ставить локально ничего не нужно.

## Куда идти под свою задачу

Подключаете стили и разбираете эталон на части темы
→ `HANDOFF.md`, разделы про порядок работ и технические требования.

Собираете шапку, футер или формы
→ `DEV_WALKTHROUGH.md`, этапы 1 и 2. Там же вопросы, на которые нужен ответ до старта.

Заводите поля в админке
→ `CMS_FIELDS.md`. Какие поля, какие лимиты, что происходит при пустом значении.

Собираете шаблон страницы из блоков
→ `TEMPLATES.md`. Какие блоки общие, какие включаются по типу записи.

Правите или добавляете стили
→ `DESIGN_SYSTEM.md`. Правило простое: значения берутся из токенов, свои числа не пишем.

Вешаете аналитику
→ `ANALYTICS.md`. Делать до сборки шаблона, не после.

Делаете верхний блок раздела
→ `TEHNOLOGII_TOP.md`.

Делаете вход по SMS
→ `AUTH.md`.

Планируете и режете на задачи
→ `BRIEF_PM.md`, там объём, зависимости и риски без технических подробностей.

Список открытых вопросов к заказчику лежит в `QUESTIONS.md`. Отвечать на них должны не вы.

## Три вещи, из-за которых теряют время

**Кэш стилей.** Ссылки на CSS идут с `?v=ГГГГММДД`, и версию надо менять при каждой правке.
Без этого браузер часами отдаёт старый файл. Выглядит это не как кэш, а как «вёрстка внезапно
поехала», и час уходит на поиск несуществующей ошибки.

**Порядок подключения.** Сначала `fonts.css`, потом `tokens.css`, потом `kit.css`, потом стили
шаблона. Порядок не косметический: правила рассчитаны на такой каскад. Склеивать всё это в один
минифицированный файл вместе с CSS темы нельзя, поедет.

**Специфичность.** В прототипе есть места, где правило написано, но не действует — его перебивает
более специфичный селектор. При переносе в тему добавится ещё её собственный CSS. Если стиль
не применился, проверяйте через `getComputedStyle` в консоли, а не чтением кода: глазами такое
не находится.

## Чего пока не хватает

Часть работы упирается в ответы, которых у нас нет. Это не забытые задачи, а внешние зависимости.
До ответов эти куски делать не стоит — переделывать придётся дважды.

Мегаменю сейчас лежит статичной разметкой, больше четырёхсот ссылок. Откуда оно берёт данные
в бою — не решено.

Поиск свёрстан на выдуманных подсказках, бэкенда нет.

Цены вписаны руками. Настоящие живут в ХП, доступа к API пока нет.

Формы отправляют данные в заглушку. Куда они должны уходить — вопрос к заказчику.

Страницы калькулятора не существует, хотя кнопка на неё есть.

По шрифту AttractiveCond нет лицензии на веб. Вопрос юридический, не технический.

Подробности по каждому пункту — в `QUESTIONS.md`, статус — в `DEV_WALKTHROUGH.md`.
