# Метрика после выката новой шапки: что починить

Дата проверки: 02.09.2026. Проверено на живом mdmprint.ru, счётчик 91973.

Новая шапка раскатана на весь сайт и работает: ошибок в консоли нет, формы и модалки живые,
заявки идут. Сломалась только аналитика. Ниже что чинить.

---

## 1. Срочно: отвалились цели быстрого заказа из шапки

В `wp-content/themes/mdm/assets/js/main.js` события навешиваются по селекторам старой шапки:

```js
document.querySelector('.header-content_desktop .popup-open[data-popup="quick-order"]')
document.querySelector('.header-menu__mobile   .popup-open[data-popup="quick-order"]')
```

Таких узлов в новой вёрстке нет. С 01.09, примерно с 13:00 МСК, в ноль ушли четыре цели:

| Цель в Метрике | Событие |
|---|---|
| Клик быстрый заказ из header десктоп | `quick_click_header_desktop` |
| Клик быстрый заказ из header адаптив | `quick_click_header_mobile` |
| Форма быстрый заказ из header десктоп | `quick_form_header_desktop` |
| Форма быстрый заказ из header адаптив | `quick_form_header_mobile` |

Шапка была главной точкой входа в заявку: больше половины срабатываний цели «Отправка заявки»
приходило именно с неё, в основном с мобильной. Сейчас этого не видно.

Вторым эффектом перестал проставляться `form.dataset.ym` — по нему на `wpcf7mailsent`
выбиралась цель формы. Заявка из шапки теперь попадает только в общую `all_quick_orders`
и в автоцель «отправка формы», без источника.

**Что сделать.** Перевесить эти четыре события на новые точки заявки: кнопку «Оставить заявку»
в топбаре (`.tb-cta`) и точку заявки в мобильном каталоге. Логику с `dataset.ym` сохранить,
чтобы отправка формы по-прежнему приписывалась источнику.

**Как вешать.** Не на классы оформления. Классы меняются при каждой правке вёрстки, и аналитика
умирает молча, без ошибок в консоли — как сейчас. Ставим на элемент `data-ym="имя_события"`
и один общий обработчик на документ:

```js
document.addEventListener('click', e => {
  const el = e.target.closest('[data-ym]');
  if (el) window.ym(91973, 'reachGoal', el.dataset.ym);
});
```

Тогда при следующем редизайне достаточно перенести атрибут вместе с кнопкой.

## 2. Полное покрытие: что в новой шапке не считается вообще

Новых элементов много, событий на них нет. Имена предлагаемые, если удобнее свои — скажите,
заведём цели под ваши.

| Событие | Где | Что покажет |
|---|---|---|
| `hdr_lead_click` / `hdr_lead_submit` | «Оставить заявку» в топбаре | замена мёртвых `quick_*_header_desktop` |
| `hdr_callback_click` / `hdr_callback_submit` | «Перезвоним» | второй канал заявки из шапки |
| `hdr_catalog_open` | кнопка «Каталог»: мегаменю и мобильный drawer | пользуются ли новым каталогом |
| `hdr_menu_click` | пункт мегаменю или подшапки, параметром `{section: 'название'}` | какие рубрики реально нужны наверху |
| `hdr_search_focus` | фокус в поле поиска, один раз за визит | доходит ли дело до поиска |
| `hdr_search_suggest` | клик по подсказке в дропдауне | работают ли подсказки |
| `hdr_search_submit` | отправка поиска | и через кнопку, и по Enter |
| `hdr_phone_click` | номер в шапке | отделить шапку от общего клика по телефону |
| `hdr_tg_click`, `hdr_max_click` | Телеграм и Макс в шапке | сейчас склеены с виджетом Битрикса в одну автоцель |
| `hdr_login_click` | «Войти» | нужен ли ЛК в шапке |
| `hdr_cart_click` | «Корзина» | переходы из шапки, отдельно от общей цели `/cart` |

Отдельно к мобильной версии: в старой шапке кнопка быстрого заказа была внутри мобильного
меню и давала основную массу кликов. В новой мобильной шапке видны только Каталог, Поиск,
Войти и Корзина, а заявка доступна лишь внутри открытого каталога. Просьба подтвердить, что
так и задумано, — если нет, это отдельная правка вёрстки, а не аналитики.

## 3. Что настраивается в Метрике, без кода

Делает маркетолог или Omar, разработчику не нужно.

**Цели под события выше.** Настройки → Цели → Добавить цель → тип «JavaScript-событие»,
идентификатор совпадает с именем из таблицы. Заводим после того, как события появятся в коде,
иначе цель будет пустой.

**Автоцель поиска чинится в интерфейсе.** Цель «Авто: поиск по сайту» слушает параметры
`q, text, query, search`, а форма шапки шлёт `?s=`. Добавить `s` в условие цели — и поиск
начнёт считаться. Сейчас там почти ноль срабатываний, и это не потому, что не ищут.

**Карты и Вебвизор уже включены**, отдельно ничего заказывать не нужно: в коде счётчика стоят
`clickmap: true` и `webvisor: true`, Вебвизор 2.0 активен, запись форм включена. Значит уже
сейчас доступны:

- карта кликов — куда жмут в новой шапке, в том числе по некликабельному;
- карта скроллинга — докручивают ли до блоков ниже шапки;
- аналитика форм — на каком поле бросают заполнение;
- записи сессий — как человек пользуется новым каталогом и поиском.

Смотреть их имеет смысл через неделю-две после выката, когда накопится статистика по новой
вёрстке. Карты кликов, снятые до 01.09, к новой шапке отношения не имеют.

**Два замечания по Вебвизору.** Он пишет содержимое полей форм, а на сайте формы с
персональными данными — это вопрос к политике конфиденциальности, не только к маркетингу.
И в настройках выключено сохранение копий страниц, поэтому старые записи проигрываются
поверх текущей вёрстки: сессии до редизайна теперь смотреть бессмысленно.

**Сегмент «мобильные» на все отчёты.** Редизайн делался в первую очередь ради мобилки,
сравнивать до и после нужно отдельно по устройствам: в отчёте «Сегментировать → Технологии →
Тип устройства → Мобильные».

## 4. Как проверить, что почини́ли

1. Открыть страницу с `?_ym_debug=1`, нажать размеченные кнопки, в консоли увидеть строки
   `reachGoal`. Проверить и на десктопе, и на мобильной ширине — точки заявки там разные.
2. Через сутки посмотреть Метрика → Отчёты → Конверсии: цели шапки снова с ненулевыми числами.
3. Отправить тестовую заявку из шапки и убедиться, что сработала не только общая
   `all_quick_orders`, но и цель формы с источником.
